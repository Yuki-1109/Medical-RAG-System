# A7 医学图片管理运行与验收

基线 A6 `7567c0391b8d6844364f9f0759896ce3a82d1d0c`；交付分支 `codex/a7-a8-phase-a-acceptance`。A7 与 A8 获用户一次性授权，完成后停止，等待 Windows 验收。一次性下载、完整测试、启动、网页操作见 [A8 综合验收](A8-阶段A综合验收.md)，结果见 [A7 验证记录](A7-验证记录.md)。

## 已实现及边界

当前库可上传 JPG/JPEG/PNG、展示原图缩略图与详情、查看真实宽高/格式/大小/哈希/时间、下载原件、编辑人工类型/分期/程度/关键词/备注、二次确认删除及失败重试。支持 K1/K2 隔离、有效图片计数和 PDF/图片联合库清理。缩略图是私有原件的浏览器缩放展示，不额外存一套改写图像；列表每页最多12张，切换/退出/卸载释放 Blob URL 与请求。

`JPEG/PNG` 是文件格式；`LESION/NORMAL/UNCLASSIFIED` 是人工类型（病灶/正常对照/未分类），默认未分类。分期和程度各100字，关键词500字，备注2000字；纯文字不接受 HTML/脚本、控制字符、额外 ID/归属/路径字段。Vue 按文字显示，不使用 v-html。人工信息仅是医生输入，系统不验证医学真实性，不分析病灶。

尚无疾病分类树、category_id 外键、疾病总览、搜索、图层、双视图、医学识图、DICOM、OCR、模型/索引/问答。C2 将增量加入同库分类实体与关联，C4～C6 加入独立结构化标注；不会用元数据覆盖原图。PDF 仍是待处理，B2/B3 才提取/分块/索引。

## 代码与 V5 数据

- `backend/.../image/`：ImageController、ImageService、ImageRepository、ImageInfo/Metadata、ImageValidator、ChannelImageInput、ImageProperties/Errors。
- `frontend/src/api/images.ts`、`image/actions.ts`、`components/ProtectedImage.vue`、`views/ImagesView.vue`、`ImageDetailView.vue`；复用统一 Session/CSRF 客户端及当前库上下文。
- `V5__create_medical_images.sql` 仅创建 medical_images，不改 V1～V4，不重建 users、knowledge_bases 或 documents。
- 图片 ID/库 ID 为 BIGINT，对外用十进制字符串；知识库非空外键 RESTRICT。原名255字、唯一受控 storage_key、JPEG/PNG、原件大小/SHA-256/宽高、人工字段、独立生命周期/清理错误、时间与按库/时间/状态索引。
- 未完成上传意图允许原件元数据为空；ACTIVE 必须完整、正大小、正宽高、64位十六进制哈希。定位路径必须与库 ID、格式一致，客户端不能提供。
- 原文件无需迁移搬动：沿用 `.storage-objects/images/<库ID>/<服务器UUID>/original.jpg|png`，默认根目录为项目 `data/originals`。

## 私有 API

全部需要 A2 ADMIN Session。写请求需要当前 CSRF；登录后刷新令牌。原件不公开静态托管，路径/账号/哈希密码不返回。

| 请求 | 功能 |
|---|---|
| GET /api/images/upload-limits | 实际大小、宽高及像素上限 |
| GET/POST /api/knowledge-bases/{id}/images | 当前所属库列表；multipart 仅一个 file |
| GET /api/images/{id} | 所属、有效图片详情 |
| PATCH /api/images/{id} | 保存完整人工信息：imageType、stage、severity、keywords、note |
| GET /api/images/{id}/content | 私有原图，实际 image/jpeg 或 image/png |
| GET /api/images/{id}/download | 原件下载，UTF-8 文件名 |
| DELETE /api/images/{id} | 指定图片清理；失败保留状态，可重试 |

不存在与非所属图片同为安全404；非法 ID 为400；匿名401；CSRF403；库删除中拒绝上传/修改、资源不可读取。库内列表只返回 SQL 所属库记录，前端再核对真实库 ID，迟到响应不能串库。跨账号夹具只在独立 Testcontainers 事务回滚中放宽单管理员约束，产品不增加公开注册或第二管理员。

内容输出前由 A5 同一文件句柄核验大小/SHA-256，再设置媒体头并流式输出。no-store/private、nosniff、sandbox CSP、受控 Content-Disposition；提供完整200文件，Accept-Ranges: none。下载额外核验 SHA-256，错误不保存。

## 格式、像素与配置

A5 校验扩展名/真实 PNG/JPEG 签名、段/块、PNG CRC、结束完整性；A7 使用 JDK ImageIO 标准解码器，先读取实际尺寸再分配像素，完整解码并拒绝解码警告或损坏数据。忽略浏览器自报 MIME，拒绝伪装、截断、格式不匹配、空图、超限。只读随机访问适配器不暴露路径、不整文件复制入堆；reader.dispose、图像 flush、输入与 A5 文件通道均关闭。最多两个并行图片校验任务。

| 配置 | 默认 | 用途 |
|---|---|---|
| APP_STORAGE_MAX_IMAGE_BYTES | 20971520 | 20 MiB，沿用 A5 |
| APP_IMAGE_MAX_WIDTH | 8192 | 像素宽度上限 |
| APP_IMAGE_MAX_HEIGHT | 8192 | 像素高度上限 |
| APP_IMAGE_MAX_PIXELS | 16000000 | 总像素上限，使用 long 乘法防溢出 |

**旧 .env 无需改动**；只在需要时追加缺少配置，不覆盖原文件/密码/根目录。尺寸采用原文件像素宽高；JPEG EXIF 方向可由浏览器显示时处理，不因此重写原件、丢 EXIF、改压缩或哈希。16MP常见RGB/RGBA像素约48～64MB，16位多通道可更高；尺寸、总像素与并行上限控制开销，不表示支持任意超大医学影像。

## 生命周期、联合计数和清理

1. 在库锁下验证归属与可用状态，先提交 A5 UUID 预约的 UPLOADING 记录，再重新锁库核验状态、流式写入/原子发布、校验/解码、提交 ACTIVE。始终有定位凭据，成功才计入 imageCount。
2. 上传失败补偿该精确预约；失败保留 DELETE_FAILED 与 cleanup_error，返回 UPLOAD_CLEANUP_PENDING，用户显式重试。数据库不可用时原 UPLOADING 意图仍保留；不扫描未知目录，不声称 DB/文件是同一个事务。
3. 单图删除先提交 DELETING，即时禁止内容访问；清理文件后删记录。占用/权限/哈希/数据库删除失败保留可重试记录。只有已提交删除意图才容许重试时原件已不存在（文件已清理、上次 DB 删除失败）。未知目录内容不自动扫删。
4. 知识库实际查询 ACTIVE documents 与 medical_images；两者非ACTIVE合计 pendingCleanupCount。库删除确认刷新真实影响并携带 expectedDocumentCount、expectedImageCount、expectedPendingCleanupCount；数量变化409，不能拿旧确认删新资料；先锁库，再用新SQL快照读取真实数量，避免等待上传锁期间保留旧数量。
5. `KnowledgeBaseMaterialCleaner` 统一接入：先持久化库删除标志，并将全部 PDF/图片标记不可访问，提交后按 PDF、图片顺序清理；保留库归属直到无任何关联记录，最后删库。不用 CASCADE。失败可显式重试剩余受控资料，K2不受影响。
6. 上传、编辑、读取、清理都按知识库锁协调；删除中不能上传。下载持锁直到流关闭，删除等待；编辑与删除不能复活记录。检测未来不匹配的 Chunk/图层表时安全拒绝，以免错误报告数量或清理。

## Windows 文件注意事项和故障处理

仅使用原 APP_STORAGE_ROOT（中文及空格路径可以），不要切换空目录来“修复”已有原件。`.env` Windows 路径建议正斜杠，如 `D:/医疗 RAG 原件`，不加引号。目录应仅由可信本机账号写入；NTFS 权限与原子移动支持必须在 Windows 实测，本次 Linux 结果不能代替。图片不提供病毒扫描或对恶意本机管理员的 OS 隔离。

| 提示 | 建议 |
|---|---|
| 超限/尺寸过大 | 查看真实限制；只用合理大小的合成教学图，不关闭像素防护 |
| 无法完整解码 | 可信查看器核对；坏压缩数据即使签名合法也拒绝 |
| 原件哈希不一致/丢失 | 保留错误、检查原目录与备份，不能直接篡改 DB 凭据 |
| 原件占用、权限不足、重试清理 | 关闭占用程序、恢复原目录权限后重试指定记录；不删整个目录 |
| 上传连接中断 | 先刷新列表核对结果与待清理意图，再决定重试，避免重复上传 |
| 确认数量变化 | 本次未删；刷新并重新确认当前影响 |
| 后端重启后登录页 | 原管理员仍保留，按 A2 重新登录 |
| V5 迁移/校验失败 | 保留 DB 与日志，核对分支及旧迁移；不修改历史 SQL、不 clean/删卷 |

A7 不自动清理未知文件，数据库/磁盘硬件损坏需完整备份恢复。Linux 实测和 Windows 待验收分开记录。
