# A2：管理员创建与后端认证操作

本任务只实现后端，不提供 A3 的登录页、管理员初始化页或新路由。前端保留 A1 启动检查页面。原需求和开发计划未修改。

## 1. 升级和运行

1. 将 A2 分支/提交同步到本机后，停止旧后端；前端不需要改动。
2. 保留 A1 的 `.env`、数据库容器和数据卷，按 README 启动数据库与后端。
3. Flyway 自动执行新的 V2：创建 `users` 表和单管理员约束。原 V1 原样保留，不删除已有数据。
4. 访问 `http://127.0.0.1:8080/api/health` 或前端启动页，仍应正常；迁移版本现在为 2。

默认端口以 `.env` 为准。以下示例使用 8080，务必始终使用同一个主机名（`127.0.0.1`），不要在同一会话混用 localhost。

## 2. API 契约

| 方法与接口 | 输入 | 正常结果/权限 |
|---|---|---|
| GET `/api/health` | 无 | A1 健康检查；公开 |
| GET `/api/auth/setup-status` | 无 | 仅 `{ "initialized": false/true }`；公开，不返回账号信息 |
| GET `/api/auth/csrf` | 会话 Cookie，如有 | `{ headerName, parameterName, token }`；首次建立匿名 Session，公开 |
| POST `/api/auth/setup` | JSON `{ username, password }` + CSRF | 201，返回 id/username/createdAt；仅首次成功，之后 409 |
| POST `/api/auth/login` | **application/x-www-form-urlencoded** 的 username/password + CSRF | 200，返回账号信息并建立认证 Session；错误凭证 401 |
| GET `/api/auth/me` | 登录后 Session Cookie | 200，返回 id/username/createdAt；未登录 401 |
| POST `/api/auth/logout` | 登录后 Session Cookie + 新 CSRF | 204；销毁 Session、清除认证及 Cookie |

初始化成功并不自动登录。用户名为 3～64 个 ASCII 字符：首位字母/数字，其余可包含点、下划线、连字符；统一保存为小写，登录不区分大小写。

密码至少 12 个字符，UTF-8 长度最多 72 字节；中文等多字节字符也计算在内，以避免 BCrypt 截断。只保存成本参数 12 的 BCrypt 哈希，不保存明文，不返回哈希，也没有默认密码或公开注册接口。

管理员创建由 PostgreSQL 唯一的 singleton_key 仲裁；应用层先检查状态，数据库约束保证并发时至多一条管理员记录。并发失败请求返回 409，不创建额外账号。

## 3. Session 与 CSRF 必须一起使用

- Session Cookie 是 `JSESSIONID`，HttpOnly、SameSite=Lax、Path=/，空闲超时 30 分钟；默认只保存在服务端内存，不要求跨应用重启保持登录。
- 本机 HTTP 默认 `Secure=false`，否则浏览器不会在 HTTP 请求中发送会话。只有实际启用 HTTPS 时，才设置可选 `SESSION_COOKIE_SECURE=true`。
- `.env` 无此新键时继续使用默认 false；启动脚本兼容旧 A1 配置。不要仅为测试 Secure 标记就对本机 HTTP 设置 true。
- 每次写请求必须带当前 Session 对应的 `X-CSRF-TOKEN`。GET csrf 返回的 token 是 Spring Security 提供的令牌，不需要自行解码。
- login 成功更换 Session ID，旧匿名 Session 不能用于访问私有接口；同时清除旧 CSRF，**登录后重新 GET csrf** 再执行写操作。
- logout 成功使旧 Session 失效；重启也会丢失内存会话，但管理员数据保留。重新获取 csrf 并登录即可。
- 不使用 Basic、JWT 或 OAuth，不生成 Spring 默认 HTML 登录页。A3 再通过同源 Vite API 代理接入这些接口。

## 4. Windows 手动验收（PowerShell 5.1/7）

下面命令在本机内存中处理密码；不要把真实密码写成命令字面值或截图公开。所有请求使用同一个 `$session` Cookie 容器。

### 首次初始化

```powershell
$base = 'http://127.0.0.1:8080'
$session = New-Object Microsoft.PowerShell.Commands.WebRequestSession
$status = Invoke-RestMethod "$base/api/auth/setup-status" -WebSession $session
$status
# 若 initialized=true，跳过 setup，使用现有管理员凭证登录，不删除 users 表。
$username = Read-Host '管理员用户名（3～64 位）'
$securePassword = Read-Host '管理员密码（至少 12 个字符）' -AsSecureString
$credential = New-Object System.Management.Automation.PSCredential($username, $securePassword)
$password = $credential.GetNetworkCredential().Password
$csrf = Invoke-RestMethod "$base/api/auth/csrf" -WebSession $session
$headers = @{ 'X-CSRF-TOKEN' = $csrf.token }
if (-not $status.initialized) {
    $body = @{ username = $username; password = $password } | ConvertTo-Json -Compress
    Invoke-RestMethod "$base/api/auth/setup" -Method Post -WebSession $session -Headers $headers `
        -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($body))
    Remove-Variable body
}
```

正常返回账号信息，不包含密码。重新查询 setup-status 为 true。再次用有效 csrf 调用 setup 应返回 **409**；不能再次创建账号。由于这是一次性操作，不通过删除数据来重复验收。

### 登录与当前账号

```powershell
$csrf = Invoke-RestMethod "$base/api/auth/csrf" -WebSession $session
$headers = @{ 'X-CSRF-TOKEN' = $csrf.token }
Invoke-RestMethod "$base/api/auth/login" -Method Post -WebSession $session -Headers $headers `
    -ContentType 'application/x-www-form-urlencoded' -Body @{ username = $username; password = $password }
Invoke-RestMethod "$base/api/auth/me" -WebSession $session
# 登录后必须重新获取令牌，替换旧 headers。
$csrf = Invoke-RestMethod "$base/api/auth/csrf" -WebSession $session
$headers = @{ 'X-CSRF-TOKEN' = $csrf.token }
```

错误密码应返回 401，正确密码返回账号信息。PowerShell 对 4xx 会抛出异常，这在负向测试中是预期结果；不要把“命令抛异常”一概当作系统失效。可用 `try { ... } catch { [int]$_.Exception.Response.StatusCode }` 查看状态码。

### 私有接口、CSRF 与退出

```powershell
# 不带 session：预期 401。
try { Invoke-RestMethod "$base/api/auth/me" } catch { [int]$_.Exception.Response.StatusCode }
# 已登录但缺少 CSRF：预期 403，并且不能退出。
try { Invoke-RestMethod "$base/api/auth/logout" -Method Post -WebSession $session } catch { [int]$_.Exception.Response.StatusCode }
# 错误 CSRF：预期 403。
try {
    Invoke-RestMethod "$base/api/auth/logout" -Method Post -WebSession $session -Headers @{ 'X-CSRF-TOKEN' = 'invalid-test-token' }
} catch { [int]$_.Exception.Response.StatusCode }
# 正确 CSRF：预期 204，通常不输出正文。
Invoke-RestMethod "$base/api/auth/logout" -Method Post -WebSession $session -Headers $headers
# 原 session 访问 me：预期 401。
try { Invoke-RestMethod "$base/api/auth/me" -WebSession $session } catch { [int]$_.Exception.Response.StatusCode }
```

### 重启后登录

停止并重启后端，数据库与数据卷保持不变；使用上面的“登录与当前账号”步骤重新获取 csrf、登录。setup-status 应仍为 true，账号 ID 不变。Cookie 若过期，可重新创建 `$session`。

测试完清理当前 PowerShell 变量（不删除管理员）：

```powershell
Remove-Variable password, securePassword, credential, csrf, headers, session -ErrorAction SilentlyContinue
```

## 5. 自动验收

在 backend 执行 `.\mvnw.cmd verify -Pintegration-test`，需要 Docker。普通 verify 不执行真实数据库集成测试。

集成测试使用独立 Testcontainers 数据库，验证 8 个同时发起的初始化请求只有一个 201、其他为 409；直接 SQL 绕过 singleton 约束也失败。测试还实际启动、停止、重启打包 jar，并验证管理员保留、旧会话拒绝、新登录成功。

私有读写探针仅存在于 `src/test` 上下文，生产包不提供假业务接口。非管理员角色的 403 使用明确的测试身份验证；产品仍只有一个 ADMIN，不扩展多用户注册。

A1 公开健康接口、pgvector、迁移幂等、前端测试与浏览器健康页需一并回归。Windows 新增 API/脚本需在本机单独执行，不能用 Linux 结果代替。

## 6. 常见状态

| 状态 | 含义 |
|---|---|
| 400 INVALID_REQUEST / INVALID_PASSWORD | 输入格式或密码长度不符合要求；不回显输入密码 |
| 401 AUTHENTICATION_REQUIRED | 未登录、会话失效或不存在当前账号 |
| 401 INVALID_CREDENTIALS | 账号或密码错误；不会区分账号是否存在 |
| 403 CSRF_INVALID | CSRF 缺失、不匹配或使用了登录前旧令牌 |
| 403 AUTHORIZATION_DENIED | 已认证但没有管理员权限 |
| 409 SETUP_ALREADY_COMPLETED | 管理员已创建，一次性初始化入口关闭 |
| 503 DATABASE_UNAVAILABLE / AUTHENTICATION_UNAVAILABLE | 数据库或账号服务暂时不可用 |

对匿名的未知私有 API 默认先返回 401；管理员认证后，不存在的接口仍返回统一中文 404。不要为了保留未知地址的匿名 404 而开放未来所有 API。

当前停止在 A2。不实现改密、找回密码、公开注册、账号管理页面或任何 A4 资料功能；若忘记本地管理员密码，恢复方案需要作为另一个经确认的任务设计，不能开放后门绕过认证。
