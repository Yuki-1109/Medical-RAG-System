# A2 管理员创建与后端认证：验证记录

日期：2026-10-13。范围严格对应原计划 A2，不包含 A3 页面或后续业务功能。

## 实际交付

- 新增 Flyway V2 `users` 表：用户名唯一、BCrypt 哈希约束、只能为 ADMIN、singleton_key 必须为 true 且唯一，从数据库保证最多一个本地管理员。
- 初始化状态仅返回布尔值；首次 setup 创建管理员，之后关闭创建入口，返回 409。初始化不自动登录。
- Spring Security + BCrypt 成本参数 12 + 服务端 Session；提供 login/logout/me，禁用 Basic，不引入 JWT/OAuth。
- Session ID 登录后更换；Cookie 为 HttpOnly、SameSite=Lax，本地 HTTP 默认不启用 Secure；通过可选配置在 HTTPS 场景启用 Secure。
- 初始化、登录、退出和所有私有写请求均执行 CSRF；登录前的旧 token 登录后失效。
- 明确公开 GET health/setup-status/csrf 和 POST setup/login；其余接口默认需要 ADMIN。内部 ERROR dispatch 允许交给安全的中文错误响应，不开放直接私有资源读取。
- 401、403、409、输入错误和数据库不可用均有安全的 JSON/中文提示；不返回密码、哈希或 SQL 异常。
- 参数校验：用户名 3～64 位并规范为小写；密码至少 12 字符、UTF-8 最多 72 字节，避免 BCrypt 截断；不把验证失败的密码值写入响应。

## 原计划四项验收的实际结果

| 原验收标准 | 实际执行与观察 | 结果 |
|---|---|---|
| 1. 首次 setup、第二次及并发 setup 不产生第二个管理员 | 首次 HTTP 201、再次 409；分别运行同名/不同名两组 8 路并发，每组恰好 1 个 201 + 7 个 409，users 恰好 1 条；直接 SQL 插入第二个 singleton 或 false 值也失败 | 通过 |
| 2. 仅存密码哈希；正确/错误密码及 me | 直接 SQL 核对 `$2a$12$` 60 位 BCrypt，实际 matches 成功；错误登录 401、正确登录 200、me 返回账号；setup/login/me 响应无密码/哈希；登录后 Session ID 更换 | 通过 |
| 3. 私有请求拒绝与 CSRF | 不带/伪造/旧 Session 访问私有读接口 401；登录后缺少或错误 CSRF 的写请求 403；有效 CSRF + 匿名私有写请求仍为 401；非 ADMIN 测试身份 403；合法 Session + token 成功 | 通过 |
| 4. logout、旧会话失效、重启后登录 | logout 204，Cookie 清除，旧 ID 回放 401；重新登录成功。实际启动打包 jar，创建和登录，结束进程、重新启动同一数据库，旧会话拒绝，原账号再次登录且 ID 不变 | 通过 |

## 未验证项、边界及运行提示

1. 用户已确认 **A1 在 Windows 本机成功启动**。本记录没有将其扩大为 A2 Windows 通过；A2 新增 API、PowerShell 5.1/7 操作和 Windows jar 重启需按操作文档实机验收。
2. 已验证 Secure=true 的 Cookie 输出，未搭建 HTTPS/TLS 服务；本机 HTTP 使用 false。A2 不扩展 HTTPS 部署功能。
3. Session 空闲超时配置为 30 分钟；本次验证退出/重启失效，没有等待整整 30 分钟做闲置超时实测。
4. 启动日志可能出现“AuthenticationProvider 已配置，UserDetailsService 不用于自动配置”的提示。本实现是显式 DaoAuthenticationProvider 绑定 AdministratorUserDetailsService，属于有意配置；真实登录已验证，不需要按提示删除认证组件。没有发现阻塞 A2 验收的功能问题。
5. 尚无前端初始化/登录/会话页面、改密或找回密码、账号管理界面、知识库等功能。不会以静态页面或假接口表示完成。

接口格式及 Windows 四项验收步骤见 `docs/A2-管理员认证操作.md`。升级保留 `.env` 和数据卷，只需重启后端让 Flyway 执行 V2。
