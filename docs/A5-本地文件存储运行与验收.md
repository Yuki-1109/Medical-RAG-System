## 根目录和大小配置

**使用默认配置无需修改现有 .env。** 相对目录默认 data/originals，从仓库根目录稳定解析：在根目录或 backend 启动，均指向同一个项目的 data/originals。启动组件只创建必要目录，不删除或覆盖已有文件。

| 可选配置 | 默认值 | 单位/含义 |
|---|---|---|
| APP_STORAGE_ROOT | data/originals | 相对项目根目录；也可用本机绝对路径 |
| APP_STORAGE_MAX_PDF_BYTES | 52428800 | 50 MiB，正整数实际字节上限 |
| APP_STORAGE_MAX_IMAGE_BYTES | 20971520 | 单张 JPG/PNG 20 MiB，正整数实际字节上限 |

自定义时只在原 .env **追加缺少的项**；已经存在的项修改该行，不重复、不用 .env.example 覆盖原文件。例如下列路径只是示例，并非你本机实际配置：

```properties
APP_STORAGE_ROOT=D:/医疗 RAG 原件
APP_STORAGE_MAX_PDF_BYTES=52428800
APP_STORAGE_MAX_IMAGE_BYTES=20971520
```

Windows .env 中建议用正斜杠，不加引号，以兼容环境脚本和 Spring properties 的转义规则。也可在启动后端前用 PowerShell 环境变量配置；.env 同名项会由脚本加载，使用一种明确的配置来源。

配置空路径、0/负数/非整数/溢出大小，目录不可用或权限不足时明确失败，不退回临时目录。相对路径要求能识别源码仓库；在任意其他目录运行独立 jar 时请设置绝对 APP_STORAGE_ROOT。前端、后端源代码和静态资源目录禁止作为存储根目录。

更改根目录不会自动搬迁旧原件。已有资料时必须保留原目录，未来按备份/迁移流程处理，不能直接指向一个空目录后删除旧目录。应用不扫描清理未知文件或目录。

## 目录结构和提交过程

```text
data/originals/
  .storage-staging/
    <服务器 UUID>/original.pdf（或 original.jpg / original.png）
  .storage-objects/
    documents/<知识库 ID>/<服务器 UUID>/original.pdf
    images/<知识库 ID>/<服务器 UUID>/original.jpg（或 original.png）
```

原始上传名称仅是内部返回凭据的元数据，不构成磁盘路径。标识只允许上述严格格式，知识库 ID 为正 BIGINT，UUID 由服务器生成；原件真实大小、SHA-256、检测类型和原名称随 StoredOriginal 返回给未来业务层。

流程：归属校验 → 生成 UUID → CREATE_NEW 临时文件 → 8 KiB 缓冲流式计数/哈希/写入 → force 并关闭文件 → 基础格式校验 → ATOMIC_MOVE 整个非空原件目录 → 返回凭据。临时文件和最终目录在同一受控文件系统内；原子移动不支持时拒绝提交，没有复制半文件的静默降级。已有对象检测及非空目录原子移动防止覆盖已有原件。

失败只补偿本次创建的临时文件和空临时目录，不递归删除未知内容，不影响其他对象。补偿失败作为 suppressed CLEANUP_FAILURE 报告，原错误仍保留；没有假成功，也不靠清空整个数据目录修复。断电/强制结束可能留下未知临时目录，A5 保留它们供后续受控处理，不自动扫删。原子提交不等于文件和数据库事务，也不承诺断电级数据库/文件一致性。

## 格式、安全读取与资源生命周期

- PDF：检测版本头、末尾 EOF/startxref、实际交叉引用位置（普通 xref 或 XRef 对象）和基本 Root 引用；不是页数读取或正式 PDF 解析，复杂/损坏文档仍需 A6 的 PDFBox 正式校验。
- PNG：签名、IHDR 字段、块长度/顺序、CRC、IDAT/IEND 和完整结尾；不解压图像、不做完整像素校验。
- JPEG：SOI/EOI、标记段长度、基本帧与扫描段、字节填充及结尾；不做完整图像解码。
- 扩展名、预期类型与内容必须一致；声明的浏览器 Content-Type 不参与信任判断。空、超限、伪装和明显损坏文件拒绝保存，不宣称病毒扫描、自动医学识图或“已索引”。
- 内部 copyTo 先在同一个文件句柄上流式核验实际大小和 SHA-256，再归零位置向调用方输出，损坏时不先输出错误字节。所有组件打开的文件句柄及时关闭，删除前关闭验证句柄并重新检查目标。
- 调用方拥有传入 InputStream/OutputStream，必须按接口契约关闭上传输入流；HTTP 输出流由响应调用方管理，存储组件不会擅自关闭。组件不向业务返回一个容易遗忘关闭的文件 InputStream。
- 路径逐层检查（含根目录及父级）、NOFOLLOW_LINKS、真实路径对照，拒绝符号链接和异常跳转；标识语法拒绝 ../、反斜杠、绝对路径、盘符、UNC、额外分隔符和编码穿越。
- 根目录只能由应用和可信本机账号写入。POSIX 新目录/文件为 700/600；Windows 使用所在目录的 NTFS 权限，应选择仅你/可信管理员可写的位置。路径检查不构成针对拥有本机管理员权限、并发恶意替换目录的操作系统隔离；不要把根目录交给不可信账号写入。
- 不注册 /uploads/**，不将原件放入 Spring/Vue 静态资源目录，未认证静态请求拒绝，已认证也没有按磁盘路径下载的路由。

## 内部接口与 A6/A7 调用契约

业务模块只注入 KnowledgeBaseFileStorage；原始 LocalOriginalStore、StorageScope 为包内实现。每次 save/copyTo/delete 都从 SecurityContext 获取已认证 ADMIN，查询真实管理员 ID，再由 A4 服务校验知识库归属；不能由前端传 owner_id。凭据中的知识库 ID 还必须与授权范围一致。

A5 没有 documents/medical_images，故不存在产品文献/图片记录与下载能力。A6/A7 的 Controller 必须接收**资源 ID**，先查询业务数据库记录、确认归属和有效状态，再使用该记录的 StoredOriginal 调用本组件。禁止从 HTTP 直接绑定存储凭据、相对路径、StorageScope 或本机绝对路径。

未来业务上传需先安全存储再保存业务元数据；数据库保存失败时用受控凭据补偿原件。删除先使资源不可访问/检索，保留清理所需的凭据和归属记录，清理成功后再完成物理记录移除；失败记录原因并可重试。删除整个知识库时要保留归属/库记录至原件清理完成，不能先删库再调用需要库归属的存储入口。A6/A7 再实现这些事务和清理业务，不在 A5 虚构。

删除区分 NOT_FOUND、ACCESS_DENIED、FILE_IN_USE（文件系统明确报告占用）、其他 IO_FAILURE，以及不支持原子提交/校验不一致等错误。文件系统只报告笼统错误时保留原因链，不猜测权限或占用。删除成功只移除指定原件，保留目录，不递归移除知识库和其他对象。
