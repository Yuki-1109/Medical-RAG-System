# A3：首次使用、登录与中文页面框架

## 已有管理员的 Windows 升级

用户已完成 A1/A2 Windows 核心验收，已有管理员 mianmian。A3 没有修改后端或数据库迁移，不需要重建账号、修改密码、清空 users 或删除数据卷。

1. A3 分支推送后，在原仓库保存好本机未提交修改，再执行 `git fetch origin`、`git switch codex/a3-authentication-ui`。本次交付只提交，不自动推送或合并。
2. 保留原 `.env` 和 medical-rag-pgdata，Docker Desktop 保持就绪；数据库容器沿用原实例。如已停止，用 `docker start medical-rag-postgres` 启动。
3. 两个 PowerShell 窗口均进入仓库根目录，分别启动后端和前端：

```powershell
# 第一个窗口，保持运行
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Start-Backend.ps1
```

```powershell
# 第二个窗口，保持运行
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Start-Frontend.ps1
```

4. 已有 node_modules 可直接启动；如需按锁文件重装，只在 frontend 执行 `npm.cmd ci`，不影响数据库。技术版本保持 A2 基线，没有新增依赖库。
5. 打开 `http://127.0.0.1:5173`（或本机 FRONTEND_PORT）。后端 setup-status 应为 true，页面进入登录。使用 **mianmian 的现有密码**，不要创建新账号或使用测试密码。
6. 登录后进入 `/app`，看到真实用户名、账号创建时间、可用导航和退出按钮；不能看到知识库列表等尚未实现的业务。

若意外显示初始化页，先检查是否使用原 `.env`、库名/端口、数据卷及后端实例。在确认前不要提交创建表单，更不能删除原数据来“修复”。查看后端 `/api/auth/setup-status` 与本机数据库配置即可排查。

## 页面与功能

| 路径 | 功能/权限 |
|---|---|
| `/` | 查询真实初始化状态及当前 Session，决定进入 setup、login 或 app |
| `/setup` | 仅未初始化时展示一次性管理员创建表单；已初始化自动转登录或已登录首页 |
| `/login` | 复用 A2 表单协议登录；已登录自动进入私有首页 |
| `/app` | 登录后的中文主布局、真实账号信息、核验登录状态、退出登录 |
| `/app/health` | 主布局内的 A1 服务检查，属于私有页面 |
| `/health` | 保留独立公开的 A1 本机服务诊断入口 |
| `/connection` | 后端不可用时的中文提示、重新连接和服务检查入口 |

左侧当前仅系统首页、服务检查可点击。知识库、文献、片段、图片、问答、会话和设置均为禁用的“待开发”标签，没有空业务接口或假数据统计。

## Windows 手动验收（现有账号）

1. 开一个无痕窗口输入 `/app/health`：应到登录页；匿名直接请求后端 `/api/auth/me` 应为 401。路由守卫不替代后端认证。
2. 输入错误密码：应显示“账号或密码错误”，停留登录页，不能看到私有页面。
3. 用 mianmian 的正确密码登录：应进入首页，显示真实账号。刷新浏览器，有效 Session 应恢复，不能依靠缓存虚构登录状态。
4. 点击服务检查：四项实际状态正常；返回系统首页，点击退出登录，再访问 `/app` 应回到登录页；之后可再次登录。
5. 在浏览器开发者工具查看 Cookie：JSESSIONID 为 HttpOnly、SameSite=Lax，本机 HTTP 无 Secure。document.cookie 不应读到它；localStorage/sessionStorage 不保存密码、令牌或登录资料。
6. 检查 setup/login/me 网络响应只含公开账号字段，不含密码或哈希。登录前后可看到 `/api/auth/csrf` 请求，登录成功后必须重新获取令牌。
7. 停止后端，另一个无痕窗口访问首页：应显示服务连接失败并能重试。恢复后端后重新连接，仍应使用现有账号，不应要求初始化。
8. 保持页面登录，重启后端，回到浏览器窗口或点击核验登录状态：应返回登录页，提示“登录会话已失效，请重新登录。”。不删库、不改账号即可验收这一分支。
9. 在 1366×768、1024×768 下检查无横向溢出，导航、表单和退出按钮可操作。较小窗口或首次初始化表单允许纵向滚动。

用户名和密码由前端在内存表单中处理；提交结束清空密码字段。不要截取真实密码、Cookie/CSRF 详情或把日志提交仓库。

## 首次初始化与自动测试必须隔离

现有数据库不要再测首次创建，也不要删除管理员。自动用例会为未初始化流程创建单独数据库，并模拟一个名为 mianmian 的测试账号；该账号的测试密码不属于用户实际账号。

```powershell

.\mvnw.cmd verify -Pintegration-test
cd ..\frontend
npm.cmd ci
npx.cmd playwright install chromium
npm.cmd run test
npm.cmd run build
npm.cmd run test:e2e
```

最后一个命令自动创建独立的 PostgreSQL/pgvector、后端 jar 与 Vite 实例，分配临时本机端口，事先确认数据库未初始化。只清理本次生成名称的临时容器及其匿名卷，**不清理现有命名数据卷**。不需要先停止正常使用的网站。

需要 Docker Desktop 的本机 socket/pipe、Java 21、已构建后端 jar 和 Playwright Chromium。测试启动器不连接远端 Docker；认证用例拒绝绕过隔离启动器执行。认证网络 trace 和视频不保存，截图仅为隔离测试界面，存入被 Git 忽略的 test-results。

## Session/CSRF 行为与边界

- API 客户端始终使用同源 `/api` 和 Session Cookie；不更改 A2 认证架构。
- CSRF 仅缓存于内存；登录后重新获取。只有后端明确以 CSRF_INVALID 拒绝执行时才刷新一次并重试，不对不确定的网络失败重复写请求。
- 私有 API 401 会清理登录状态并转登录；错误密码的 INVALID_CREDENTIALS 不伪装为会话过期。跳转目标仅允许已实现的本机私有路径，拒绝外部 URL。
- 刷新和路由切换重新核验服务端；窗口恢复焦点时核验会话。闲置约 30 分钟后也会核验一次，不以高频轮询不断续期。
- 自动测试只对隔离后端临时配置 1 分钟 Session，实际等待 65 秒测过期。生产后端仍为原 A2 30 分钟；本次没有完整等待生产 30 分钟超时。
- 不实现 A4 知识库 CRUD、文献/图片业务、模型设置、统计工作台或问答。
