## Windows 待验收、限制和风险

1. A5 没有 Windows 实测结果。按运行文档 fetch/switch 后执行 `.\mvnw.cmd verify -Pintegration-test`，需要 Docker Desktop Linux containers；同样使用隔离数据库/目录，不针对已有管理员和原件。
2. 理想结果为单元 52、集成 48，共 100 项；Windows 不支持 POSIX 的一项会明确跳过，创建符号链接缺少权限时两项链接测试也会说明原因。这些不能算通过；其余核心路径、故障注入与真实持久化测试仍必须成功。Linux 三项都实际执行且通过。
3. Windows NTFS 中文/空格绝对路径、原子目录移动、原生共享锁、句柄关闭及联接点行为须以本机结果为准。组件不向调用方返回待关闭的文件句柄，自己的通道都由 try-with-resources 关闭；Linux 结果不替代 Windows 检查。
4. 根目录只能由可信本机账号写入。逐层 NOFOLLOW/realPath 防护针对应用输入和已有路径跳转，不宣称可抵御恶意本机管理员并发替换路径；Windows 应使用合适的 NTFS 权限。不是病毒扫描，也不保证任意损坏文件全部可由基础校验识别。
5. A5 基础格式校验不等于 PDF 正式解析或完整图片解码；PDFBox 页数与严格结构验证留 A6，图像解码和像素限制留 A7。
6. 存储原子提交不等于数据库/文件分布式事务，也不承诺断电后两者一致。未知临时对象保留，不自动扫删；后续业务须记录失败、标记资源不可用、受控重试，且知识库归属记录应保持到清理结束。

没有已知阻塞 Linux A5 验收的未修复问题。Windows A5 尚待实机验收；上传、预览、业务资料统计、模型/检索/问答、分类/标注均未实现。
