## 2. 执行约定与优先级解释

1. 严格按 A → B → C → D → E 开发。每次只执行一个经用户确认的小任务；完成后停止，等待下一次确认。
2. P0 是最终必须交付的功能，P1 在规定阶段逐项增强，P2 放入选做清单，未经确认不进入开发。P0 分布在多个阶段，A 完成不代表 MVP 已完成。
3. 每个小任务交付实际可运行的代码、必要迁移、启动命令、配置样例、验收步骤和测试结果，并回归受影响的已有功能。未实现功能明确标注，不能提供假成功接口、静态业务数据或假检索日志。
4. 需求变更先列出优先级及对数据、页面、测试和进度的影响；技术栈替换、收费服务新增、重大功能删改先征求用户意见。
5. 中文界面；面向 Windows 本地运行和本科答辩；单个本地管理员，不提供公开注册。知识库及资源的归属校验全部在后端执行。
6. 医学事实只来自当前知识库证据；不联网补答案，不自动识图诊断，不训练模型。历史消息只用于理解指代，不能当成医学证据。
7. 原 PDF、原图不可被编辑覆盖；人工更正、人工批注及图层分别保存，修订可溯源。

### 需求内部表述差异的处理

- 总表将 PDF 页码跳转列为 P1，但第 3.5 节明确要求 P0。本计划按较严格的细则执行：A6 提供按页预览，B7 引用跳页，C1 片段跳页；精确文字高亮仍是 P2。

- 会话历史属于 P0，而第 9 节将完整多轮历史放在 D。本计划 B7 保存真实会话、消息和引用并支持基本回看，D1 完成新建、继续、重命名、删除与历史页面，D2 再加入 P1 问题重写。
- B2 基础分块尊重段落、句子和数值单位；复杂章节识别与结构优化列为 D7 的 P1，不能以“结构优先是 P1”为由在基础版任意破坏医学语义。
- 阶段 D 先完成 D1、D5 涉及的 P0，再实现其他 P1；阶段 E 的发布与本地部署验收仍按原文保留，不因标注 P1 就省略 Windows 交付。

## 3. 技术方案与目录规划

采用一个 Spring Boot 应用、一个 PostgreSQL 数据库及本机文件目录，前后端分离开发，最终由后端托管 Vue 构建产物。不引入微服务、Redis、消息队列、MinIO、Kubernetes 或 Agent 框架。

| 层次 | 采用技术 | 引入时点 |
|---|---|---|
| 前端 | Vue 3、Vite、Element Plus、Vue Router；建议 TypeScript | A1 |
| 后端 | Java 21 LTS、Spring Boot、Maven Wrapper | A1 |
| 认证 | Spring Security、服务端 Session、BCrypt、CSRF | A2 |
| 数据 | PostgreSQL + pgvector；建议 Spring Data JPA 管业务实体，向量查询由 Spring AI/JDBC 执行 | A1 验证扩展，B3 使用向量 |
| 迁移 | Flyway，增量 SQL 迁移，避免靠运行时自动改表交付 | A1 |
| RAG | Spring AI、至少一种兼容的聊天/Embedding API | B1 |
| PDF | Apache PDFBox、PDF.js | A6 / B2 |
| 图层 | Vue Konva | C4 |
| 存储 | 受控的本机持久化目录，原件与结构化编辑数据分离 | A5 |
| 测试 | JUnit、Spring Boot Test、真实 PostgreSQL 集成测试；前端关键交互用 Vitest/浏览器自动化 | 随任务引入 |
| 发布 | Docker Compose、Windows PowerShell 启停脚本、GitHub Release | E |

版本策略：A1 核对官方稳定版本、Spring Boot/Spring AI 兼容矩阵、Java/Node 支持范围及许可证，再锁定版本和依赖锁文件。Java 21 为建议基线；Node 使用届时受支持且符合 Vite 要求的 LTS。此处不把未经验证的依赖组合写成已经验证可用。

| 阶段 | 新增或完善的表 | 关键约束 |

索引不得只按相似度查全库后由前端过滤；查询同时限定归属、知识库、文档有效性、Chunk 启用状态和有效版本。Embedding 维度/模型版本明确记录，重建完成前不混查不兼容向量。

文件与数据库不能共用一个事务：上传使用临时文件、校验、受控落盘及失败补偿；删除先使记录不可访问/检索，再清理原件，清理失败记录原因并可重试。后续 B/C 索引更新沿用这一生命周期，不让失效文件或旧片段继续返回。

## 5. 阶段 A：最小网站骨架，细拆为 8 个小任务

目标：真实连接数据库，创建本地管理员，管理多个知识库，上传和查看 PDF/JPG/PNG；重启后账号、资料记录和原件仍然存在；未登录请求不能读取私有数据。

### A1：环境与可启动工程

**功能与交付**

- 核对并锁定依赖版本及许可证；Vue/Vite/Element Plus 与 Spring Boot 的最小工程。
- PostgreSQL 真实连接、Flyway 初始化、验证 pgvector 扩展可用，向量业务留到 B。
- 提供真实健康状态，不泄露配置或凭证；数据库不可用时报告真实错误。
- 配置本地地址、同源开发代理、中文统一错误格式；配置模板和 `.gitignore`。
- 给出 Windows 安装依赖、建库、启动前后端的命令及配置说明；不要求先完成整套 Compose。
- 主要文件：`frontend/package.json`、入口文件、Vite 配置；`backend/pom.xml`、Maven Wrapper、应用入口及配置；迁移目录、配置模板、环境说明。

**验收**

1. 从锁文件安装前端并完成构建；后端构建并启动，能真实连通 PostgreSQL。
2. 验证数据库扩展与迁移状态，第二次启动不会重复执行迁移。
3. 断开数据库，健康状态或启动错误必须反映连接失败。
4. 检查端口只在回环地址监听、配置模板无密钥、数据目录被 Git 忽略。

**完成边界**：能启动工程并检查数据库；尚无账号和资料操作，不宣称可交付完整网站。

### A2：管理员创建与后端认证

依赖 A1。新增 `users` 迁移、账号服务、安全配置及认证测试。

**功能与交付**

- 首次创建一个本地管理员；初始化状态只返回必要信息，创建成功后关闭再次初始化入口。
- 并发初始化也只能产生一个管理员，不允许绕过入口再次公开注册。
- 实现 login/logout/me、Session Cookie、BCrypt、CSRF；统一未登录/无权限响应。
- 默认保护所有私有接口；公开范围仅含必要初始化/登录及非敏感状态。
- 本地 HTTP 的 Cookie 使用 HttpOnly、合适的 SameSite；Secure 随实际 HTTPS 环境配置，不能在 HTTP 下错误配置导致无法登录。

**验收**

1. 首次 setup 成功；第二次及并发 setup 不产生第二个管理员。
2. 数据库仅有密码哈希；正确密码能登录，错误密码失败，me 返回当前账号。
3. 不带会话访问私有测试接口被拒绝；缺少/错误 CSRF 的写请求被拒绝。
4. logout 后旧会话失效；重启后账号可再次登录。会话是否跨重启保留不作为要求。

**完成边界**：可通过 API 创建管理员并登录；前端登录流程在 A3 完成。

### A3：首次使用、登录与中文页面框架

依赖 A2。新增初始化页、登录页、主布局、路由守卫、统一 API 客户端。

**功能与交付**

- 根据真实初始化状态进入“创建管理员”或“登录”；完成后进入系统。
- 登录状态加载、退出、会话过期返回登录页、中文错误反馈。
- 前端请求携带会话与 CSRF，路由守卫与后端认证共同生效。
- 先展示已有模块入口；后续功能标注待开发或暂不展示，不用假页面表示已完成。

**验收**

1. 浏览器完成首次创建 → 登录 → 刷新 → 退出 → 重新登录。
2. 未登录直接输入私有页面地址，会转到登录；直接访问后端仍被拒绝。
3. 错误密码、后端不可用和会话过期有可读提示。
4. 检查网络响应无密码哈希、Cookie 为 HttpOnly，界面适配普通笔记本。

### A4：知识库 CRUD 与后端隔离

依赖 A3。新增知识库迁移、服务/API、知识库卡片与表单。

**功能与交付**

- 真实列表、新建、改名/简介、进入当前库、二次确认删除。
- 每个库绑定 owner_id；读写删都校验归属；当前库切换来自真实 ID。
- 文件数量从实际记录统计；没有文件时的 0 是真实计数。
- 暂无文件时实现空库删除；A6/A7 加入删除非空库的影响说明与清理。

**验收**

1. 建立库 K1/K2，编辑 K1，刷新及重启后均保留。
2. 取消删除无变化；确认删除只删除目标库；非法/空名称被拒绝。
3. 未登录 CRUD 被拒绝；不存在的库返回明确错误。
4. 用集成测试夹具构造非当前账号所属资源，读写删均拒绝；测试账号仅用于隔离测试，不加入产品注册流程。

### A5：本地原件存储与安全读取基础

依赖 A4。新增可复用的文件存储组件、配置和存储测试，供 A6/A7 使用。

**功能与交付**

- 配置持久化根目录；安全生成文件名、校验大小及实际格式、计算 SHA-256。
- 原始名称仅作元数据；文件位置由服务端生成，不能由上传名称决定。
- 文件按资源 ID 经归属校验读取，不公开直接访问上传目录，不接受任意本机路径。
- 临时文件与失败补偿、删除清理错误处理；中文/带空格 Windows 路径兼容。
- 建议默认限制 PDF 50 MiB、单图 20 MiB，可由本地配置调整；这是可调整的实施默认值，非原文既定指标。

**验收**

1. 实际写入测试文件并重启组件，字节和 SHA-256 一致。
2. 同名文件不覆盖；`../`、绝对路径等名称不会导致越界写读。
3. 超限、非法格式、写入失败不会留下有效业务记录或成功提示。
4. 使用 Windows 路径规则相关测试；真实 Windows 跑通在 A8/E 再核实。

**完成边界**：这是存储基础子任务，浏览器上传分别在 A6/A7 验收；不新增无用途的演示上传 API。

### A6：PDF 上传、列表、预览与删除

依赖 A5。新增 `documents` 迁移、上传/列表/详情/内容/下载/删除接口，文献页和 PDF.js 预览组件。

**功能与交付**

- PDF 原件实际落盘，保存库 ID、原名、大小、校验值、页数、时间及状态。
- PDFBox 用于实际格式校验及页数读取；文字提取、分块、Embedding 留到 B。
- 列表和详情、PDF.js 按页查看、下载、二次确认删除。
- A 阶段上传后显示“待处理”；不能显示“已索引”。不开放假的重新解析按钮。
- 删除非空知识库前显示影响范围；确认后让关联文献不可访问，清理文件和记录。

**验收**

1. K1 上传真实 PDF，列表页数等与原件一致，预览与下载成功，下载校验值一致。
2. K2 列表没有 K1 的 PDF；未登录/非归属请求无法上传、读取、下载、删除。
3. 假扩展名、损坏 PDF、超限文件被拒绝；密码保护且无法读取的 PDF 给出明确原因。
4. 刷新与重启后仍能预览；确认删除后列表、详情和原件读取均失效。
5. 扫描 PDF 若格式有效可作为原件待处理保存；A 不声称能提取文字，B 对空文本明确判定失败。

### A7：医学图片上传、原图列表与人工基础信息

依赖 A6。新增 `medical_images` 迁移、接口及图片列表/详情。

**功能与交付**

- 实际 JPG/PNG 上传、格式及尺寸校验、原图保存、元数据与校验值。
- 当前库内列表、原图缩略展示和详情、下载、删除、知识库真实图片计数。
- 人工填写/修改类型（病灶/正常对照/未分类）、分期、程度、关键词和备注；明确这些是医生填写内容。
- 疾病分类实体与三级图库在 C2 加入；A 图片可未分类，不提供假疾病分类树。
- 标注编辑和双视图在 C4～C6；此时只展示原图，不显示没有图层的假切换效果。
- 补齐非空知识库删除时文献/图片数量、影响说明及文件清理。

**验收**

1. K1 上传 JPG/PNG，查看原图及人工信息，修改后刷新/重启仍存在。
2. 下载原图与上传文件 SHA-256 一致；同名上传不能覆盖原图。
3. K2 图片列表不含 K1 资料；无会话或无归属的内容请求被拒绝。
4. 假图片、损坏文件、超限体积或过大像素尺寸被拒绝，不形成假成功记录。
5. 删除图片/非空知识库后，数量准确、原件读取失效、其余知识库不受影响。

### A8：阶段 A 集成回归与 Windows 验收说明

依赖 A1～A7。补齐自动化测试、Windows 操作说明及验收记录，修复发现的问题。

**综合验收脚本**

1. 用全新测试数据库/目录启动，创建管理员并登录。
2. 建立 K1/K2；K1 上传合法测试 PDF、JPG、PNG；K2 上传独立文件。
3. 编辑库简介与图片备注，记录文件校验值。
4. 停止前后端，重启 PostgreSQL 和应用；重新登录，检查账号、两个库、记录和原件。
5. 切换知识库检查列表；不带 Cookie 直接请求私有列表、原件和写接口，均被拒绝。
6. 验证取消删除、确认删除、非法上传、路径穿越、CSRF、非归属 ID 请求。
7. 删除 K1 后无法再读取 K1 资料；K2 数据及原件仍然可用。
8. 检查提交候选文件没有密钥、上传内容或数据库；前端构建与后端测试通过。

在 Windows 实机按说明执行启动/停止与上述核心流程；若当前执行环境只有 Linux，则报告“Linux 已验证，Windows 待实机验收”，不能把文档审查当成 Windows 测试通过。

**A 完成时尚不可用**：PDF RAG 解析与索引、模型设置、问答、完整疾病分类/图层、片段编辑、多轮历史、Compose 分发。清楚列出这些边界后停止，等待用户确认 B。
