## 3. 网页功能验收

1. 打开“我的知识库”：没有库时显示真实空状态，不生成演示卡片。若此前已创建过测试库，列表应显示原数据。
2. 点击“新建知识库”，创建 K1、K2，填写不同简介。两张卡片显示不同 ID、真实时间、文献 0 / 图片 0。当前没有资料模块，这些确实为空库。
3. 编辑 K1 为“K1 修改后”并更换简介。K2 名称和简介应保持原样。刷新后修改仍在。
4. 进入 K1：顶部显示当前库名称和 ID；通过“选择或切换知识库”切到 K2，名称、ID、URL 和详情同时切换。刷新或直接输入该详情 URL，后端重新核验后恢复该库。
5. 在 K1 详情点击“删除知识库”，先取消。K1 仍在；开发者工具 Network 不应产生 DELETE 请求。
6. 再次删除并“确认删除”：回到列表，K1 消失，K2 保留。当前库标识变为“尚未选择”，不能继续把 K1 当作有效上下文。
7. 验证持久化时应在删除 K1 前进行：在后端窗口 Ctrl+C 后重新执行启动命令。重新登录，K1/K2 和 K1 修改应都保留，管理员不要求重新创建。刷新前端不能绕过服务端 Session。
8. 新建时尝试空名称、全空格、101 字符或超 2000 字符简介：中文提示且不提交；直接非法 API 请求也应被后端拒绝。
9. 直接访问 `/app/knowledge-bases/9223372036854775807` 应提示“知识库不存在或无权访问”，当前库清空。`/app/knowledge-bases/abc` 提示 ID 无效，不发不合法资料请求。
10. 另开浏览器窗口删除正在查看的库，返回原窗口恢复焦点或刷新：重新核验后提示库不存在，当前库清空。
11. 在无痕窗口直接输入知识库详情地址：先转登录，登录后回到正确的真实库 ID。退出后不能继续查看私有页面。
12. 在 1366×768 / 1024×768 检查卡片、编辑表单、切换和删除按钮；允许纵向滚动，没有横向溢出。

当前库只在内存和合法详情路由中表示，不使用 localStorage/sessionStorage 保存凭证或私有资料。刷新详情页可恢复该库；在系统首页刷新而 URL 无知识库 ID 时显示“尚未选择”，需要重新进入或切换。删除、退出及会话失效会清理已选状态。没有周期轮询不断续期；窗口恢复焦点会重新核验。

## 4. 权限和 API

| 方法与路径 | 行为 |
|---|---|
| GET /api/knowledge-bases | 仅当前管理员的列表 |
| POST /api/knowledge-bases | 创建；仅接受 name/description |
| GET /api/knowledge-bases/{id} | 归属校验后的详情 |
| PATCH /api/knowledge-bases/{id} | 更新名称和简介，提交完整两个字段；description 可省略为空 |
| DELETE /api/knowledge-bases/{id} | 只允许 A4 空库删除，成功 204 |

所有写接口要求当前 Session Cookie 与 X-CSRF-TOKEN；复用 A2/A3 客户端，登录后重新获取 CSRF。缺少/错误 CSRF 返回 403。未登录请求不允许读取或写入；有匿名 CSRF 的写请求仍返回 401。没有令牌时安全过滤器可能先返回 CSRF 403，同样不能写入。

owner_id 只从后端已认证的用户确定。请求中额外的 owner_id、ownerId、id、demo 等字段一律 400，不能修改归属或伪造演示属性。URL ID 校验为正十进制 BIGINT；JSON ID 为字符串，避免 JavaScript 整数精度损失。不存在与非所属库统一 404，错误不包含资源名称、简介或归属，避免泄露存在性。

**不要在实际数据库创建第二个管理员来测权限。** 以下后端集成测试会在独立容器中建立跨用户夹具，只在可回滚的测试事务里暂时放宽 singleton 约束，产品迁移与公开初始化接口始终只允许一个管理员。测试验证列表排除其他账号资源，详情/修改/删除拒绝，数据库原内容不变。

在网页登录后可在 Network 查看真实 CRUD 响应；匿名浏览器直接访问 `http://127.0.0.1:8080/api/knowledge-bases` 应返回 401。不要公开截图真实 Cookie、CSRF、密码或数据库配置。

## 6. V3 与后续扩展边界

V3 只新增 knowledge_bases：BIGINT identity 主键、owner_id 外键 RESTRICT、名称 VARCHAR(100) 非空/非空白、简介长度上限 2000、is_demo 默认 false、创建/更新时间，及 owner_id+更新时间索引。users/V1/V2 原样保留，没有预设资料和新管理员。

演示属性目前仅预留并可显示，不创建演示资料，也不允许普通编辑请求更改标志。以后合法素材导入时通过独立迁移/受控导入设置。

KnowledgeBaseMaterials 明确验证 documents/medical_images 尚未存在，知识库响应才能返回空库数量；存在后续资料表时拒绝返回误导的 0 或进行空库删除。A6/A7 在此组件和仓库映射接入实际统计、非空删除影响与文件清理，保持前端 documentCount/imageCount 接口。未来资料外键必须使用 RESTRICT；当前没有危险级联。不要靠删除表、禁用约束或关闭 Flyway 规避保护。

常见问题：

| 现象 | 检查 |
|---|---|
| 意外出现创建管理员页 | 先核对原 .env、DB 端口/库名、容器与数据卷；不要提交创建，不删数据 |
| Flyway 校验失败 | 确认使用 A4 分支、V1/V2 未被修改；保存数据后排查，不 clean/repair 或禁用校验掩盖问题 |
| 列表错误或连接超时 | 检查后端健康、8080 及原数据库，恢复后点刷新；页面不把错误伪装成空列表 |
| ID 不存在/无权访问 | 返回列表选择有效 ID；不要通过改 owner_id 绕过 |
| CSRF 403 | 刷新页面、重新登录；客户端只对明确 CSRF 拒绝刷新令牌并重试一次 |
| 检测到资料模块 | 当前代码与后续数据库版本不匹配，切回配套版本；不要删资料表 |

A4 完成后停止。下一任务 A5 仅为安全本机原件存储基础，不提前做 PDF/图片上传或 RAG。
