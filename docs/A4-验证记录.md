## 2026-10-14：Windows 重启测试日志清理兼容性修复

### 用户报告与原因

Windows 执行 `.\mvnw.cmd verify -Pintegration-test`：原有单元 4 项通过，集成 42 项中 0 Failures、2 Errors。AuthIT 和 KnowledgeBaseIT 两个真实重启测试在 finally 的 `Files.deleteIfExists(log)` 报“另一个程序正在使用此文件”。报错属于测试清理，不是用户已经完成验收的网页业务失败。

原实现用 ProcessBuilder.Redirect.appendTo 将子进程输出直接指向临时文件。等待子进程退出后马上删除日志，没有单独控制输出文件句柄的完成时机。Windows 不允许删除仍被占用的文件；当前没有 Windows 原生句柄追踪结果，不能认定某个具体 JVM 版本或杀毒程序就是锁持有者，也未在 Linux 重现原 Windows 文件锁。

### 修复措施与范围

1. 新增仅测试使用的 RestartTestApplication：子 JVM 输出合并到 PIPE，由父测试进程的日志线程写入自己创建的唯一临时文件；子进程不直接继承该日志文件重定向句柄。
2. 发送终止信号、等待退出（正常等待 10 秒，必要时强制终止再等 5 秒），再等待管道读到 EOF、日志任务关闭文件及线程结束；显式关闭输入/输出/错误流。专项验证发现 Process.destroy 会提前关闭读取管道，已改用 ProcessHandle 发送信号，避免吞掉 Stream closed 异常或丢失退出输出。
3. 用 try-with-resources 管理整次重启测试，前一次退出和日志关闭后才启动下一次。测试断言失败也清理自己的进程和日志；清理错误保留为异常，不覆盖原断言（通过 suppressed exception 保留）。
4. 文件系统占用导致删除失败时只做最多 50 次、间隔 100ms 的有限重试（最长等待约 4.9 秒）；永久占用仍抛原异常并失败。其他 IO 错误不重试；中断保留标志并报告。没有忽略异常、deleteOnExit、长期保留日志或跳过测试。
5. 两个重启测试的业务断言不降低；只修改 backend/src/test 和 A4 说明记录。业务代码、前端、Flyway、依赖、原需求与开发计划均不改动。
6. 新增 7 项辅助组件测试：大输出 stdout/stderr 排空及重启追加、断言失败清理/保留非所属文件、启动失败释放句柄、短暂占用恢复后实际删除、永久占用失败、普通 IO 错误不掩盖、中断传播。Linux 还检查终止时的 shutdown 输出；Windows 不支持正常终止时仍验证真实退出、日志关闭和删除。
